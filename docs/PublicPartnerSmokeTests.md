# Public Partner Smoke Tests

Use development data or temporary UI fixtures with zero, one and multiple linked partners, unknown birthdays, a deceased partner and duplicate names. Keep database, migration and seed files unchanged. Include a partner whose own id differs from its associated Cherry Kin id.

- In Genealogy, verify the root section headings are `Parent`, `Parents` and `Parent & Spouses` for zero, one and multiple partners respectively. All linked partners appear directly below the root, including partners without birthdays. A sole partner's name aligns with the root name; with two or more partners, all partner names are slightly indented.
- Verify missing partner birthdays leave Age and Birthed blank. Dated partners use the public full-month date format. Partner Spouse cells show the associated Cherry Kin Full Name; Cherry Kin Spouse cells show all partner names separated by commas.
- Click the root name and a linked partner name separately. Both must navigate to the root's parent; neither changes the top-level root when it has no parent.
- Check all four descendant sections still contain only Cherry Kin with their original counts and order. A descendant's partners appear as rows only after that descendant becomes the root.
- In List, verify one row per Cherry Kin and one row per partner, including partners without birthdays. With Search empty, the row count must equal people plus partners for every sort except Death Day, which omits all entries with a NULL Death Day. Partners without birthdays have blank Age and Birthed cells. Duplicate names remain separate rows, including multiple partners associated with the same Cherry Kin.
- Click a List partner name and verify the associated Cherry Kin becomes the genealogy root, regardless of the partner's own id.
- Verify a sole partner displays the associated Cherry Kin's Children count, including 0, whether or not Birthday is known. Multiple partners linked to the same Cherry Kin must all have blank Children, even when Search only shows one of them. Children sorts numeric counts descending with blanks after 0. Test all existing sorts: Death Day omits Cherry Kin and partners with NULL Death Days; missing Birthdays and Spouses stay visible at the bottom of their respective sorts. Missing birthdays are not highlighted by Upcoming Birthday. Check preserved List sort when switching views. No Age sort or direction control is added.
- Search for partial partner names and associated Cherry Kin names with mixed case and surrounding spaces. Match Full Name OR Spouse only; dates and ages must not match. Genealogy highlights matches and List filters them. Check empty results and Reset.
- Compare a deceased partner's age, dagger, accessible label and popup with Cherry Kin behavior. Check partner birthday/deathday supply the age at death, death date and hypothetical age today. Test hover, focus, click, Enter, Escape and outside dismissal, plus touch activation at a mobile width.
- Verify partners never have phone icons. Genealogy Cherry Kin retain phone details; List contains no phone controls. Check indentation and popup positioning at desktop and mobile widths.
- Confirm the public server read selects no legacy spouse columns from people, and the server-to-client data contains independent people and partners records. Check the unchanged admin list still loads.

Phase 2 implementation verification: unit tests, desktop/mobile Edge fixture checks, public development-database List and navigation checks, and the unchanged admin list read passed. Temporary fixture routes were removed after verification.

All-partner List update verification: sorts other than Death Day retain the same total as the admin All view (people plus partners); Death Day only includes entries with known death dates. Partners without birthdays displayed blank Age and Birthed, remained searchable and navigable, and had no Upcoming Birthday highlighting. Missing sort values remained last.
